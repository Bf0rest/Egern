# 接手一份第三方 Egern 脚本（固定顺序）

> 目标：**在 10 分钟内**得到「它需要什么 / 会渲染成什么样 / 哪里有隐患」，而不是通读 1000 行。

> 以下命令都在 **kit 根目录**（本文件所在目录）下执行。

## 0. 先看头注

多数 Egern 脚本头部会写 env 用法。**头注是作者的说法，不是事实** —— 下面两步会核对。

## 1. 静态体检

```bash
node scripts/kit/inspect.mjs <url 或 路径>
```

要重点看四行：

| 行 | 意义 |
|---|---|
| 请求端点 | 它会往哪发请求（顺带是隐私体检：有没有你不认识的域名） |
| env 键 | 它需要哪些配置；标了「动态取键」的说明静态数不全 |
| ⚠️ 官方未提供 | 它读了平台**没有**的 ctx 字段 ⇒ 那些分支永远拿不到值（`appearance` / `colorScheme` 是最常见的两个） |
| ⚠️ 疑似无效属性 | 官方属性表里没有的属性（如 `justifyContent`、`border`）⇒ 写了也不生效 |

## 2. 动态普查

```bash
node scripts/kit/inspect.mjs <src> --run --family systemLarge --env K=V
```

这一步会真的跑一遍（模拟 ctx，请求返回空占位），把**真实 DSL 树**的节点统计、未支持节点、
树内非官方属性、文本片段打出来。静态会低估（节点常由 `text(...)` 这类辅助函数拼出），这一步才是权威。

**跑不起来就是结论**：报 `IMPORT_FAILED` / `NOT_A_SCRIPT` 时到此为止，不要绕过。

**跑起来了但树很瘦**（≤2 个节点，文本像「获取失败 / 请先填写密钥 / 连接失败」）⇒ 它落在**降级分支**，
这个形状不是真形状：先补 `--env`（缺配置）或 `--mock`（缺数据形状）再重跑；
两样都补不出来，就当「这份脚本的形状在本机测不出来」写进结论 —— 别拿降级态去改版式。
（`--family` 只出主屏四档，锁屏三档会 exit 2，见 SKILL.md。）

## 3. 出稿看形状

```bash
node scripts/kit/draft.mjs <src> --family systemLarge --out draft.html
```

打开 `draft.html`：
- 划过元素 → 「名字 · 左边 · 尺寸」；点一下**钉住**；再划别的元素给 **Δ左/上/右/下/中** —— 这就是跟人沟通「往左一点」的量化方式
- 读数条给全量（含层级路径，同一段文案出现多次时靠它区分）
- 数据是**占位**，别拿内容下结论

## 4. 要真实形状，喂真实样本

```bash
node scripts/kit/draft.mjs <src> --family systemMedium --mock sample.json
```

`sample.json` = 它某个端点的真实响应。多端点时要写适配器（见 `lib/load.mjs`）。

## 5. 改之前先记住

- **改动落在源码，不落在稿页**：稿页是产物
- 改完**重跑第 1~3 步**；`selfcheck.mjs` 确认工具本身没坏
- 「真机上会不会裁切 / 对不对齐」—— 稿页回答不了，只能上真机
