# 稿子纪律（什么时候可以信这张图）

## 可以信的

- **层级结构**：谁在谁里面、有几个子节点（来自真实 DSL 树，不是猜的）
- **相对位置与相对尺寸**：元素之间的 Δ左/上/右/下，谁比谁宽（同一张稿内比较）
- **文本内容**：脚本真的产出了什么字
- **显式声明的数值**：`gap`、`padding`、`width/height`、字号

## 不可以信的

| 不能信 | 为什么 |
|---|---|
| 稿页的绝对像素 | CSS flexbox 近似 Yoga，不是同一个布局引擎 |
| 字重 / 字型 / 笔画粗细 | Windows 上是 Inter + Noto Sans SC，真机是 SF Pro + 苹方 |
| 行高细节 | 稿页默认 1.25×，真机按字号 ≈1.35× |
| 「这里被裁掉了」 | 稿页的 `overflow:hidden` 会裁；真机怎么表现要真机看 |
| 玻璃 / 锁屏着色 | 那部分由系统渲染，脚本画不了也测不到 |

## 三条硬规矩

1. **跑不起来就只报事实**，不许自己编一棵树出稿。
2. **假数据必须标注**：所有请求默认返回空占位；要真实形状就 `--mock` 喂真实样本，并在结论里写清来源。
3. **要判「真机上对不对」，只能上真机**：截图量墨迹，或者写一个探针组件挂上去看。

## 已知的 Egern 事实（会影响你的判断）

- `ctx` **没有** `appearance` / `colorScheme` ⇒ 别设计「跟随系统深浅」的分支（`inspect` 会帮你抓）
- `image` 默认 `resizeMode` 是 **contain**（不是拉伸）
- `stack.direction` 默认是 **row**；`alignItems` 默认 **center**
- `widget` 根容器按内容宽度摆子节点（**flex-start**），但**含裸 `spacer` 的行会被撑到可用宽度**
- 根上写 `borderWidth/borderColor` **不生效**（官方只对 `stack` / `image` 生效）
- `font` 整个省略 = `body` = 17pt（不是 11pt）
